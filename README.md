## 📦 О проекте

**YawaReleaseBot** — это локальное приложение (Next.js + встроенная база SQLite) с удобным веб-интерфейсом, которое переносит **только релизы** из одного закрытого репозитория GitHub в другой:

- ✅ Копирует **тег, название, changelog (описание)** релиза из репозитория-источника;
- ✅ Скачивает **бинарные файлы релиза (ассеты)** из приватного репозитория;
- ✅ Создаёт идентичный релиз в репозитории-приёмнике **от имени второго аккаунта**;
- ✅ **Никогда не переносит исходный код** — только артефакты релиза;
- ✅ **Тег и нумерация версий всегда совпадают** с репозиторием-источником.

> 🟦 Слово **Release** в названии выделено фирменной подложкой — это визуальный акцент на главной функции бота.

## 🚀 Быстрый старт (локально на ПК)

### Требования

- **Node.js 24 LTS** (минимум 22; Node 20 снят с поддержки) и **npm** — версия зафиксирована в `.nvmrc`;
- Два GitHub-аккаунта с **Personal Access Tokens** (scope `repo`).

> Внешняя база данных **не требуется** — приложение использует встроенный файл SQLite и создаёт его автоматически при первом запуске.

### Шаги

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/ВАШ-ЛОГИН/YawaReleaseBot.git
cd YawaReleaseBot

# 2. Установите зависимости
npm install

# 3. (необязательно) Настройте путь к базе
cp .env.example .env
# → при желании задайте DB_FILE (по умолчанию ./data/yawareleasebot.db)

# 4. Запустите приложение в режиме разработки
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) и настройте подключение репозиториев прямо в интерфейсе «🛠 Подключения».

## 🔑 Как получить токены GitHub

1. В GitHub перейдите **Settings → Developer settings → Personal access tokens → Tokens (classic)**;
2. Создайте токен и отметьте scope **`repo`**;
3. Используйте токен:
   - **Аккаунт 1 (источник)** — читает приватный репозиторий;
   - **Аккаунт 2 (приёмник)** — создаёт релизы и загружает файлы.

## 🏗 Сборка на GitHub Actions

Репозиторий подготовлен для автоматической сборки на GitHub (**Node 24**, actions v5 — без предупреждений об устаревшем Node 20). При пуше в `main`, на pull request или вручную (`workflow_dispatch`) выполняется `.github/workflows/build.yml`:

1. Устанавливаются зависимости (`npm ci`, а при отсутствии `package-lock.json` — `npm install` с предупреждением);
2. Генерируются типы маршрутов и прогоняется проверка типов (`next typegen`, `tsc --noEmit`);
3. Выполняется production-сборка (`npm run build`).

> ⚠️ **Обязательно коммитьте `package-lock.json`.** Без него `npm ci` не работает, а кэш зависимостей отключается. Если файл отсутствует в вашей копии — выполните `npm install` локально и закоммитьте созданный `package-lock.json`.

### 📥 Скачивание собранного билда

**После каждого успешного запуска** (пуш в `main`, pull request, ручной запуск) конвейер упаковывает standalone-сборку и прикладывает её как **артефакт** к запуску Workflow:

1. Откройте вкладку **Actions** → нужный запуск (**Build & verify**);
2. Внизу страницы, в разделе **Artifacts**, скачайте `YawaReleaseBot-<ветка>-<sha>` (zip);
3. Тег/релиз для этого **не требуется** — артефакт появляется всегда.

> Артефакты хранятся 30 дней (настраивается в `retention-days` шага `Upload build artifact`).

### 🏷 Выпуск полноценного GitHub Release

Полноценный **GitHub Release** собирается отдельным конвейером **Release** (`.github/workflows/release.yml`): он параллельно строит portable **`.exe`** (на Windows) и standalone-бандл (на Linux), после чего прикрепляет всё к релизу через официальный `gh` CLI.

Запустить можно двумя способами:

**Способ 1 — пуш тега:**
```bash
git tag v1.0.0
git push origin v1.0.0
```

**Способ 2 — вручную из интерфейса GitHub:**
1. Откройте **Actions** → **Release** → **Run workflow**;
2. Введите тег (например, `v1.0.0`) и запустите.

После этого на вкладке **Releases** появится `YawaReleaseBot v1.0.0` с файлами:
- `YawaReleaseBot-1.0.0-portable.exe` — **готовое приложение для Windows**;
- `YawaReleaseBot-v1.0.0-<sha>.zip` / `.tar.gz` — standalone-сервер для других ОС.

### ▶️ Запуск скачанного standalone-архива на ПК

Нужен только Node.js 24 — исходный код, `npm install` и база данных не требуются:

```bash
# внутри распакованной папки
PORT=3000 node server.js  # Windows PowerShell: $env:PORT=3000; node server.js
```

> База SQLite (`./data/yawareleasebot.db`) создаётся автоматически при первом запуске.

### 🖥 Portable-приложение Windows (`.exe`) — рекомендуемый способ

Каждый GitHub Release содержит **один файл** `YawaReleaseBot-<версия>-portable.exe` — это полностью автономное приложение, собранное на GitHub Actions. **Устанавливать ничего не нужно**: ни Node.js, ни npm, ни базу данных — всё уже внутри.

**Как пользоваться (3 шага):**

1. Откройте вкладку **Releases** и скачайте `.exe` последней версии;
2. Запустите двойным кликом;
3. Приложение само создаст базу, поднимет сервер и откроет окно — **сразу приступайте к настройке подключений** на вкладке «Подключения».

> Данные хранятся в `%APPDATA%/YawaReleaseBot/` (база `yawareleasebot.db` + лог `main.log` для диагностики). Сам `.exe` можно держать где угодно — хоть на флешке.
